# Release 2 — annual dossier inspection and cross-source conflicts

Implemented offline in Codex Cloud on the existing feature branch, 15 November 2026. The [annual operating profile](release2-sec-operating-statements.md) now has a versioned read-only dossier consumer and an explicit fictional UI. It adds no acquisition, provider/model call, storage, sender or valuation calculation. Actual holding dossiers remain unconnected to financial packets.

## Original-input admission and display model

`company-dossier-operating-v1` carries symbol/CIK/assessment/retrieval, supplied original companyfacts and one to three explicit annual `{period,receipt}` entries. `admitDossierOperating` in `src/utils/dossierOperating.ts` independently rechecks every receipt through `validateSecOperatingReceipt`; it rejects malformed/widened identities or periods, duplicates, core-profile substitution, source limits, invalid payloads and inconsistent filing metadata across periods. Invalid admission withholds the whole new annual package. Explicit source failures remain needs-data, with no invented retrieval or observed financial zeros.

`reviewDossierOperating` validates the existing financial receipt, core statement packet and annual package once each. It produces a presentation model, not another normalized receipt or an eligibility certificate. Existing v1/core presentation is unchanged when the annual package is absent. The new model only withdraws or folds supplied declarations; it cannot create financial values, select an authoritative source, choose a latest vintage or grant source/issuer/valuation/decision/aggregation authority.

The consistency checks distinguish:

- **Matching supplied fields:** an identical tag/unit/period/value/accession/form/filing-day declaration can be folded from the additional annual cards when a corresponding source card is actually visible in the original financial section. A matching input that is only inside a derived calculation's advanced explanation is not folded. Folded originals remain inspectable in Annual input sources. Field agreement is not independent corroboration or proof of matching accounting/dimensional context.
- **Same-field disagreements:** different values or filing vintages for the same tag/unit/period withhold both competing figures and every legacy calculation that uses that field. Unrelated declarations remain available. A newer vintage is not automatically preferred. Hidden contested values are removed from source-inspection cards too.
- **Different revenue definitions:** `Revenues`, contract revenue excluding assessed tax and net sales remain separate, including when their values differ. They are never summed or substituted. A consistent alternative cannot override a conflict involving the exact tag used by an existing calculation.
- **Filing disagreements:** incompatible form/filing-day declarations for a shared accession withhold all affected figures and dependent calculations. Filing-focus FY/FP are compared where both raw profiles supply them; absent legacy fiscal labels are not invented. If a core statement filing is implicated, all additional core figures and their valuation-input checks are withdrawn atomically.
- **Issuer/assessment disagreements:** independently admitted core and annual packets must still share the same declared CIK and assessment, even when there is no legacy financial reference. Disagreement withholds both scopes; the view cannot mix two issuer or clock declarations under one ticker.

Amounts cannot leak back through Sources, Overview counts or valuation checklists after withdrawal. The model retains bounded constant reasons, recognized tags, dates, accessions and counts, but does not return conflicting monetary rows, unrecognized source prose, private fields or raw error text. It does not reconcile restatements or authenticate a filing. Existing separately loaded scopes remain available after a missing/invalid annual package when there is no admitted contradictory evidence.

## Compact interaction and fixture boundaries

The development-only **Add fictional statement inputs** action now explicitly loads both core and annual fictional packets. Each factory gets a fresh source copy. No additional network request or new global navigation is added. Closing and reopening the fictional dossier clears those packets.

Growth and Financial health contain a collapsed **Additional annual declarations** panel. The user chooses an explicit annual period before figures appear; no latest period is guessed. That period choice persists across dossier sections but is valid only for the same symbol/CIK/assessment and a still-supplied period. Failed/changed packets immediately derive fresh empty/withheld views; an old value cannot survive through local state. Source failures or loaded-but-missing coverage give an explanation instead of an impossible empty selector.

The matching UI example binds fourteen annual declarations across two periods, folds two matching cash-flow/payment source cards, and leaves twelve additional cards across the selected sections/periods. It preserves a reported net loss and context-unverified DDA/share compensation. Different revenue definitions remain visibly qualified. Original tag/unit/index/value, filing-focus labels, dates, retrieval and conservative publication bounds remain expandable; references are constructed and original filings are not retained or verified.

The new `src/data/companyOperating.fictional.json` and `qa/fixtures/dossier-operating.fictional.json` are dedicated UI fixtures. Their invented current cash-flow/payment values match the existing dossier's 10/15 declarations. The earlier fixed-pin native-export demo retains its separate 20/25 declarations and files unchanged; a regression case proves those inputs conflict with the dossier and withdraw FCF. No runtime repair, source-value rewriting or silent reconciliation is performed. These are separate invented examples, not competing real issuer claims.

Normal production assets exclude fictional actions and raw fictional payloads. The optional read-only consumer/registry is included with the deferred dossier code for future supported supplied inputs; it makes no request by itself. Actual holding disclosures still pass no financial packet. The native byte reader and Node crypto/file helpers remain outside browser code. No data is added to council/model context, Opportunities scoring, accounting, history, journaling or exports. No EBITDA, growth, margin, total-debt or valuation formula is added by the annual path.
